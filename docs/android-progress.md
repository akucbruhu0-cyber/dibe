# DIBE לאנדרואיד: מסמך התקדמות

התוכנית המלאה נמצאת בהיסטוריית הסשן. כאן מופיעים רק ההחלטות, מצב הבדיקות והפערים, כדי שאפשר יהיה להמשיך מכאן בסשן אחר.

## מבנה
- `android/`: אפליקציית Kotlin + Compose (M3), מודול `app` אחד, DI ידני ב-`DibeApp.kt`.
  - חבילות: `engine` (גשר JNI), `audio` ו-`service` (הקלטה, קבצים, FGS), `models` (קטלוג והורדות), `data` (היסטוריה), `export` (9 פורמטים), `ai` (סיכום), `settings`, `ui/*`.
- `server/crates/dibe-core`: ‏`Engine` ו-`LiveCore`, שהועברו מ-`vibe-server`, ו-resampler. המחשב והטלפון מריצים את אותה לוגיקה.
- `server/crates/dibe-jni`: ‏`libdibe.so`.
- `scripts/android/build-native.sh`: בונה שתי גרסאות של ggml ו-JNI אל `android/app/src/main/jniLibs/arm64-v8a/`: ‏`libdibe.so` (fast, ‏armv8.7a עם i8mm) ו-`libdibe_compat.so` (‏armv8.2-a+dotprod).
- `promo-video/src/onboarding/`: אנימציות הפתיחה ב-Remotion. הרינדור (`pnpm --dir promo-video render:onboarding`) כותב אל `res/raw`.

## החלטות
- **Compose נייטיב ולא WebView:** ממשק ה-React קשור ל-Tauri, ל-sidecar ולחלונות.
- **JNI ישירות ל-Rust ולא שרת HTTP מקומי:** אין צורך ב-tokio, axum ו-reqwest בטלפון.
- **שירות אחד, `DibeService`, עם type דינמי:** ‏`microphone`, ‏`mediaProjection` או `dataSync`.
- **הורדות דרך DownloadManager של המערכת:** הוא ממשיך אחרי ניתוק ומציג התראה משלו.
- **פורמט `transcript.vibe.json` זהה למחשב:** אפשר להעביר תיקיות פרויקט בין המכשירים.
- **צבעים:** הניטרלים של המחשב. primary ירוק `#145A1E` במקום הכחול, accent `#3CB54A`, פונט Rubik.
- **אנימציות פתיחה:** וידאו בלי טקסט. הטקסט נייטיבי בעברית ובאנגלית. ‏VideoView בלי תלות חדשה, ו-poster כש-reduce motion פעיל.
- **arm64-v8a בשתי גרסאות:** ‏`NativeEngine` קורא את `/proc/cpuinfo` ובוחר. עם i8mm ו-bf16 נטענת fast. עם asimddp נטענת compat, שאיטית ב-9% ונותנת פלט זהה. בלי dotprod מוצגת הודעה ברורה שהמכשיר לא נתמך. בלי זה, כל טלפון בלי i8mm (Snapdragon 888 ומטה) היה קורס ב-SIGILL.
- **אורך ההקלטה לא מוגבל בזיכרון:** פענוח הקובץ נכתב ל-WAV של 16kHz על הדיסק דרך resampler עם מצב בין בלוקים. התמלול רץ בחלונות של 10 דקות שנחתכים ב-200ms השקטים ביותר. ה-JNI קורא את המערך בלי להעתיק אותו.
- **כיוון טקסט:** בכל סגנונות הטקסט ב-theme מוגדר `TextDirection.Content`. כל פסקה מקבלת את הכיוון מהמילים שלה, כך שעברית מוצגת נכון גם בממשק באנגלית.
- **v1 בלי:** diarization, ייבוא URL, dictation, handoff, ו-20 שפות ממשק נוספות.

### באגים שנמצאו בבדיקות ותוקנו
- שורות שכל התוכן שלהן "." (רעש בכיתה): מסוננות בגבול המנוע (`isSpoken`) לכל הנתיבים. כנראה קורה גם במחשב, ולא תוקן שם.
- עברית בממשק באנגלית הוצגה LTR, עם הנקודה בצד הלא נכון: תוקן ב-theme עם `TextDirection.Content`, ובשורות החי עם כיוון לפי השורה.
- "חזרה לחי" הופיע בלי גלילה, כי `reverseLayout` מעגן את הרשימה ל-key של הפריט הראשון: עכשיו יש מעקב מפורש אחרי הקצה החי.
- אנדרואיד 17 סירב ל-FGS מסוג `mediaProcessing` ("type none"), ו-`promote()` החזיר false אחרי fallback מוצלח ל-dataSync, כך שעבודת קובץ נכשלה: עכשיו רק הקלטה דורשת את הסוג המדויק.
- קובץ בלי דיבור הציג "האפליקציה נסגרה באמצע ההקלטה": ההודעה ו"לתמלל עכשיו" מוצגים עכשיו רק לרשומה בלי `modelPath` (שחזור).
- כותרת ה-PDF וצבע ה-HTML היו בכחול של המחשב: הוחלפו בירוק המותג.
- החלונית הצפה כיסתה את נגן התמלול: לכל מסך יש עכשיו שוליים תחתונים משלו.

### ממצאי code review (19) שתוקנו
SIGILL בלי i8mm (קריטי), OOM בהקלטות ארוכות, כשל לכידה שקט, timeout של dataSync באנדרואיד 15, שינוי שם או מחיקה בזמן תמלול, מודלים באחסון חיצוני (עברו ל-`filesDir`), intent ששותף והופעל שוב מ-Recents, קבלת `file://` ממקור זר, מפתח API ב-http לשרת שלא ב-LAN, URI grants שהצטברו, "שמירה בשם" אחרי מוות של התהליך, טעינה ותמלול שלא היו אטומיים, מחיקת מודל טעון, כלל ה-autoSummarize, threadpool ‏(`map_while`), הצפנת מפתח על ה-main thread, קצוות resample, שם קובץ הקלטה כפול, ו-`displayName` על ה-main thread.
